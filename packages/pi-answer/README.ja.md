# pi-answer

アシスタントメッセージから質問を抽出し、対話的な Q&A 画面で回答する。英語版は [README.md](./README.md)。

[mitsuhiko/agent-stuff の `answer.ts`](https://github.com/mitsuhiko/agent-stuff/blob/main/extensions/answer.ts) の移植。

## インストール

```sh
pi install npm:@335g/pi-answer
```

`pi install` はユーザ設定（`~/.pi/agent/settings.json`）に書き込む。プロジェクト設定（`.pi/settings.json`）に書き込むときは `-l` を付ける。

## 使い方

- `/answer` — 直近のアシスタントメッセージから質問を抽出する
- `/answer 2` — その 1 つ前のアシスタントメッセージから抽出する（`3`、`4` と遡れる）
- `ctrl+.` — `/answer` と同じ

`/answer N` の `N` は、新しい方から数えたアシスタントメッセージの位置である。数えるのは本文のあるメッセージだけで、引数を省略すると `1` になる。

流れ: 設定した抽出モデル（既定ではセッションモデル）で質問を抽出し、1 問ずつ枠内に表示する。続いてフリースペース（メモ用）、全体の確認画面と進み、1 つのメッセージとして送信する。送信は新しいターンを開始する。

キー:

- 回答中: `Tab`/`Enter` 次へ、`Shift+Tab` 前へ、`Shift+Enter` 改行、`1`-`9` 候補を挿入、`Ctrl+X` 質問を除外、`Esc` キャンセル
- 確認画面: `Enter`/`y` 送信、`Esc`/`n` 最初の質問へ、`l` 最後の質問へ
- 破棄の確認: `Enter`/`y` 破棄、`Esc`/`n` 編集に戻る。何か入力したときだけこの確認が出る。回答が空のまま `Esc` を押すと即座に破棄する。

抽出モデルは質問に `options`（短い回答候補を 2〜4 個）を付けることがある。候補は質問の下に並び、回答が空のときだけ `1`-`9` でカーソル位置に挿入できる。この条件があるため数字はそのまま入力でき、候補を選んだあとに注記を足せる（`はい` → `はい、ただし本番のみ`）。`Ctrl+X` は質問を捨てる。捨てた質問はメッセージに含まれず、残りの質問は番号が詰められる。

## 設定

`pi-answer.json` は `/answer` のたびに読むため、再起動は要らない。プロジェクトのファイルはグローバルの設定をキー単位で上書きし、信頼済みのプロジェクト（`ctx.isProjectTrusted()`）でのみ読む。

| 場所 | 範囲 |
|------|------|
| `~/.pi/agent/pi-answer.json` | グローバル |
| `.pi/pi-answer.json` | プロジェクト |

```json
{ "lang": "ja_JP.UTF-8", "model": "anthropic/claude-haiku-4-5" }
```

- `lang` — `LANG` と同じ形式のロケール（例 `ja_JP.UTF-8`）。言語の接頭辞だけを見る。未設定なら `LC_ALL`、次に `LANG` を使う。
- `model` — 抽出モデル。`provider/modelId` か `modelId` のみ。未設定ならセッションモデル。利用可能なモデルに一致しないときは警告を表示し、セッションモデルを使う。

送信されるテキストは番号付きの Markdown ブロック（`### Q1: ...` / `Context: ...` / `Answer: ...`）である。フリースペースに文章があれば `### Notes` 節が続く。回答しなかった質問はメッセージから省くため、番号の飛びは「スキップした」を意味する。回答もメモも無いときは何も送信しない（`No answers to submit`）。確認画面には送信するメッセージをそのまま表示し、切り詰めもプレースホルダ行も無い。

ラッパーは TUI のフォーカスを内側のエディタに渡し、エディタが `CURSOR_MARKER` を出すようにする。これにより IME の変換中テキスト（未確定の日本語入力）は枠の下端ではなく回答行に出る。
