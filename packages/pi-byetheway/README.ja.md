# pi-byetheway

[English](./README.md)

セッションの内容を踏まえて質問できるが、やりとりをセッションに残さないスペース。`/btw` で開き、これまでの
経緯について質問し、痕跡を残さず閉じる。結論だけを残したいときは `ctrl+n` でやりとりを1つのメッセージに
再構成して本体セッションへ送る。

## インストール

```sh
pi install npm:@335g/pi-byetheway
```

`pi install` はユーザ設定（`~/.pi/agent/settings.json`）に書き込む。`-l` を付けるとプロジェクト設定
（`.pi/settings.json`）に書き込む。

## 使い方

- `/btw` — スペースを開く
- `alt+b` — `Esc` で退避したスペースを再開する

| キー | 動作 |
|------|------|
| `Enter` | 質問を送信 |
| `Shift+Enter` | 改行 |
| `Esc` | 退避して通常のエディタに戻る（状態は保持） |
| `ctrl+d` | 破棄して閉じる（失うものがあれば確認する） |
| `ctrl+n` | やりとりを本体セッションへ渡す（下記） |
| `ctrl+u` / `PageUp` / `PageDown` / 入力が空のときの `Up`・`Down` | 履歴スクロール |

これらのキーは btw パネルにフォーカスがある間だけ効く。渡すキーが `ctrl+p` ではなく `ctrl+n` なのは、
**本体のエディタでは `ctrl+p` がモデルの切り替え**であり、渡すつもりで押すとモデルが黙って変わるため。
`ctrl+n` は本体のエディタでは未割り当てなので、押し間違えても何も起きない。

回答は流れてくる。生成中も入力は続けられるが、`Enter` は無視される。失敗した質問は入力欄に戻るので
打ち直さなくてよい。理由（プロバイダのエラー、空回答、中断）はフッターだけでなく入力欄の上の本文に表示する。

## 本体セッションへ渡す（`ctrl+n`）

スペースの目的は「勝手に本体へ漏れないこと」なので、受け渡しは明示的になっている。

1. `ctrl+n` が観点を尋ねる。
2. `1`〜`4` でプリセット（結論と根拠／決定と理由／未解決の問い／却下した案）を挿入する。そのまま書き換えても、
   別の観点を打ち込んでもよい。空のまま `Enter` なら既定の観点になる。
3. `Enter` でやりとり全体を1つのメッセージに再構成し、プレビューを出す。
4. プレビューは編集できる。`Enter` でユーザ発言として送信、`Esc` で戻る、`ctrl+r` で整形し直す。

`5` は再構成せず生のログをプレビューする。整形が外したときの逃げ道。整形プロンプトでは「一人称で書く」
「相手側の提案には帰属を残す（『別案として〜』）」「本文だけを出力する」を指示している。帰属を落とすと、
本体エージェントが他人の提案をあなたの判断として読んでしまうため。

## 何が送られて、何が送られないか

- セッションファイルには何も書かない。`appendEntry` もメッセージ追加もしていない。
- プレビューで `Enter` を押すまで、本体エージェントの文脈は変わらない。
- btw のリクエストは、本体が送るはずだったメッセージ（compaction 適用済みのセッション分岐）と、ここまでの
  やりとりを積む。**ツール定義は送らない**ので、記録はテキストに潰す。ツール結果は `[read の出力] ...`、
  本文もあるターン内のツール呼び出しは `[read]` になる。ツール呼び出しだけのターンは丸ごと落とす。残すと
  呼び出しごとに `[bash]` の行が並び、「ツール呼び出しで答える」例として読まれてしまうため。画像は
  `(画像は省略)` に置き換える。長いセッションでは約250メッセージが約35になり、本文は1文字も失わない。
- この prefix は本体セッションと同一なので、prefix キャッシュを持つプロバイダでは通常キャッシュ料金になる。
  ただし compaction していない長いセッションでは、1ターンごとのリクエストは大きい。

## 制限

- btw のエージェントはファイルを読めないしコマンドも実行できない。セッションの文脈だけで考える。
  読み取り専用ツール（`read` / `grep` / `find` / `ls`）は次の増分。
- セッションの記録にはツール呼び出しが含まれるため、ツールを渡していなくてもモデルがツールを呼ぼうとすることが
  ある。btw の system prompt で明示的に禁じている。返答が空で返ってきた場合（ツール呼び出しを拒まれたときの
  典型）はエラーとして表示し、質問を入力欄に戻す。
- 文脈は `/btw` を開いた時点のスナップショット。その後に本体で進んだ作業は入らない。退避から再開しても
  同じスナップショットを使う。
- 退避中のスペースは、セッションが差し替わると破棄される。

## 開発

```sh
node packages/pi-byetheway/selfcheck.ts
```

2つの自己チェックを実行する。文脈の変換（ツール呼び出し・結果のテキスト化、画像の除外、同一ロールの
結合、アシスタントメッセージのメタデータ保持）と、pi に接する部分（登録されるコマンド・ショートカット・
イベント、および private な `ModelRuntime.stream` がレシーバを保つこと）。
